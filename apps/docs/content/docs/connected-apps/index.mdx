Open **Connections** from the sidebar, choose a service, and finish authorization in your browser. OpenFolks turns that connection into tools supported engines can use.

<ProductScreenshot name="docs-connected-apps" alt="The OpenFolks connected-app marketplace" caption="Search the marketplace or review every account from the Connected tab." />

## Official packaged app

The signed desktop app registers its own installation with OpenFolks's managed connected-apps service. You do **not** need to find or paste a Composio key.

1. Open **Connections**.
2. Search for Gmail, GitHub, Slack, Notion, or another toolkit.
3. Select **Connect**.
4. Finish OAuth in the browser window that opens.
5. Return to the Desk and ask a folk to use the service.

The installation identity is stored in Electron's operating-system-backed secure storage. Provider OAuth tokens remain with Composio. They are not written into briefs or the renderer.

## Source builds

The managed service is a convenience for official packages. A source build can use your own Composio project and `COMPOSIO_API_KEY`. See [Self-hosted Composio](./self-hosted-composio.mdx).

## Several accounts

Connect more than one account for the same toolkit and give each a clear alias such as `work`, `personal`, or `client-acme`. When several accounts could perform an action, OpenFolks requires an explicit choice instead of silently replacing the first connection.

## Disconnecting

Disconnecting revokes the grant at the provider. It does not only hide the account in the local UI. Other accounts for the same toolkit stay connected.

<Callout type="info" title="No Connect key on official builds">
  Current official builds provision connected apps automatically. A Composio project key is only needed when you run the integration yourself.
</Callout>
